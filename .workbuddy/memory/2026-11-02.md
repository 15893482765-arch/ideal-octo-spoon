## 部署到腾讯云服务器（111.230.155.58）

将项目以「精简部署」方式部署到 Linux 服务器（CentOS 7，2G 内存 / 2 核，Docker 26.1.4 + compose v2.27.1）。

**部署形态**：单后端容器同时托管前端页面与 API + PostGIS + Redis，共 3 个容器。
- 关闭 Qdrant 向量检索（`QDRANT_ENABLED=false`，降级为关键词检索）
- 关闭本地 embedding 模型（`EMBEDDING_ENABLED=false`，省内存）
- 去掉 MinIO，改用 `STORAGE_BACKEND=local`（`/app/backend/.data/storage`，挂 appdata 卷）
- 保留 AI 对话（DeepSeek OpenAI 兼容端点）
- worker 数 4 → 2

**新增文件**（均在 infra/）：
- `infra/Dockerfile.prod`：生产镜像，构建上下文=仓库根，容器结构复刻仓库（`/app/backend/...` + `/app/frontend/dist`）。**关键点**：`app/main.py` 的 `_frontend_dist_dir()` 用 `parents[2]/frontend/dist` 定位前端，所以源码必须放在 `/app/backend/app`，否则解析成 `/frontend/dist` 导致首页 404。
- `infra/docker-compose.prod.yml`：精简 compose（postgres/redis/migrate/api）。已加 mem_limit（pg 512m、redis 128m、api 768m）。
- `infra/.env.production`：生产环境变量。
- `.dockerignore`

**踩坑记录**：
1. `uv sync` 从官方 PyPI 下载在国内极慢（31 分钟仅 5s CPU 时间，实为网络卡死）。解决：Dockerfile 加 `UV_DEFAULT_INDEX` / `UV_INDEX_URL` 指向清华源 `https://pypi.tuna.tsinghua.edu.cn/simple`，首次依赖安装降到 ~7.5 分钟。
2. `Settings` 里 `s3_endpoint_url` / `s3_access_key` / `s3_secret_key` 是**无默认值的必填字段**，即使 `STORAGE_BACKEND=local` 也必须提供，否则 migrate/api 启动即 pydantic ValidationError。compose 里补了占位值。
3. 后台（run_in_background）执行的 ssh 命令会被沙箱拦截读取 `~/.ssh/id_ed25519`；必须前台执行（超时会自动转后台，且已通过放行）。
4. 前端 dist 打进镜像后由 FastAPI `serve_frontend` 托管，无需 Nginx。

**服务器目录**：`/opt/qinshuang`（backend/ frontend/dist/ infra/）
**启动命令**：`cd /opt/qinshuang && docker compose -f infra/docker-compose.prod.yml --env-file infra/.env.production up -d`

## 修复：新建账号角色下拉只有「系统管理员」

**根因**（生产库 roles 表只有 1 行）：
- `bootstrap_initial_admin()` 只创建 `SYSTEM_ADMIN` 一个角色；
- 其余 5 类角色仅由 `demo_account_seeder._ensure_roles()` 播种，而它受 `DEMO_DATA_ENABLED` 开关控制、且写入的是 **DEMO 数据集**；
- 生产部署按红线设 `DEMO_DATA_ENABLED=false`，因此 6 类角色从未被创建。

**修复**：新增 `infra/seed_roles.py`（幂等），补齐缺失角色并挂在现有 SYSTEM_ADMIN 所在的
`(dataset_type=PRODUCTION, dataset_id=29e69e7c-3ae5-590c-ac0c-3d20cfd774f3)` 下。
执行方式：`docker cp` 进容器后 `docker exec -w /app/backend qinshuang-api python seed_roles.py`。
结果：roles 表 6 行（SALES_REP/REGIONAL_MANAGER/SUPERVISOR/FINANCE/SYSTEM_ADMIN/SUPPLIER）。

**注意**：用户已自行在 UI 完成首次改密（`must_change_password=false`、`password_version=2`），
初始口令 `Qinshuang@2026` 已失效。
