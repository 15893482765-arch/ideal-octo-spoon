# 沁爽饮料分销管理平台 · AI Agent 任务卡开发流程 v1（Python + PostgreSQL）

> 配套文档：《沁爽饮料分销管理平台-PRD-Python实施版-v1.1.md》  
> 技术栈：前端 Vite + React + TypeScript + shadcn/ui；后端 Python 3.12 + FastAPI + Pydantic v2 + SQLAlchemy 2；PostgreSQL 16 + PostGIS + Redis  
> 开发模式：单 Agent 串行 + 任务卡驱动；一张卡 = 一次会话 = 一个 commit

本流程把 PRD 拆为 30 张可执行任务卡。每张卡都规定依赖、边界、测试编号和完成条件。除标注可并行的卡外，必须按顺序执行；跨卡回改后必须重跑被改卡测试。

## 〇、使用方法

1. 从 T01 开始，一次只给 AI 一张卡，不把后续卡混入当前会话。
2. 每张卡连同“给 AI 的固定前缀”一起发送。
3. AI 完成后，人必须亲自运行验收命令并逐条核对人工验收。
4. 每张卡单独提交，提交信息用 `T<NN>: <名称>`。
5. 测试编号 `Q001` 起全局唯一；不得用“应该通过”代替真实测试结果。
6. 遇到需求缺口先查 PRD。PRD 未定义的业务算法写入二期待办，不允许 AI 自行发明。

# 一、技术选型与工程约束

## 1.1 后端与数据库

- FastAPI 负责 OpenAPI 契约、异步 I/O 与依赖注入；Pydantic v2 负责请求/响应边界。
- SQLAlchemy 2 使用显式事务；Alembic 管理不可逆迁移；禁止在 Router 中 `commit()`。
- PostgreSQL 16 + PostGIS 负责坐标、距离校验和后续路线能力；Redis 只用于缓存、限流、幂等、分布式锁与任务锁。
- 异步任务统一使用 Celery + Redis。核心业务事务不交给 Celery；通知、导出、图片处理、指标快照在事务提交后异步执行。
- 金额为 `BIGINT` 分；业务层 `Decimal`；禁止 float。箱数为 `NUMERIC(12,2)`，是否只允许整箱由 SKU/规则校验。

## 1.2 后端分层

```text
api/          当前用户、Pydantic 校验、调用 service、Response Schema
services/     业务规则、状态机、事务、权限二次校验、审计
repositories/ SQLAlchemy 查询；复杂统计集中在 metrics_repository
models/       ORM 模型，不直接作为 API 返回
schemas/      Request/Response 与字段脱敏
core/         配置、认证、权限、异常、幂等、审计、日志
mcp/          MCP 工具适配，只调 Service，不直连数据库
workers/      Celery/Dramatiq 任务，只处理非核心事务工作
```

统一错误结构：`{code,message,details,request_id}`。业务错误抛领域异常，由全局异常处理器转换；不得把堆栈、SQL、密钥返回前端。

## 1.3 前端与 UI 规范

前端使用 React + TypeScript + shadcn/ui、TanStack Table、React Hook Form + Zod、date-fns、Lucide、Recharts。地图封装为适配器，不把供应商 SDK 对象泄露到业务组件。列表筛选、搜索、分页全部写入 URL。

设计令牌：品牌青绿色 `#0F766E`；成功 `emerald`；提醒 `amber`；危险 `rose`；信息 `sky`；中性 `slate`。状态必须使用颜色 + 图标 + 文字，不得只用颜色。

必须复用：`Money`、`DataTable`、`StatusBadge`、`MetricCard`、`AuditTimeline`、`ConfirmDialog`、`EvidenceViewer`、`ScopeNotice`、`MapPoint`、`AiExecutionPreview`。

反面清单：手写重复表格、金额不经 `Money`、筛选不进 URL、空态无下一步、用前端隐藏代替后端鉴权、AI 直接写库、原始照片/定位可覆盖、展示明文密码。

# P0 · 地基与安全（T01–T06）

## T01 · 工程初始化与开发约定

**目标**：前后端、本地基础设施和质量门禁可运行。

**要做什么**
- 建立 `backend/`、`frontend/`、`infra/`、`docs/`；后端使用 uv 管理依赖，前端使用 pnpm。
- 后端加入 FastAPI、Uvicorn、Pydantic Settings、SQLAlchemy async、Alembic、asyncpg、GeoAlchemy2、Redis、Celery、boto3、python-multipart、PyJWT、Argon2、pytest、pytest-asyncio、httpx、ruff、mypy。
- 前端初始化 Vite/React/TS/Tailwind/shadcn，加入 typecheck、lint、Vitest 与 Playwright smoke。
- Docker Compose 启动 PostgreSQL/PostGIS、Redis、MinIO；密钥只从 `.env` 读取，提交 `.env.example`。
- 建立统一错误、request-id、中间件、健康检查和 `docs/CONVENTIONS.md`。
- 建立 `docs/test-traceability.csv` 与 CI 校验器；从 T01 起逐卡维护 `Q → 测试文件/节点 → 执行命令 → 夹具 → PRD 规则/验收场景`，禁止重复、缺失和悬空引用。

**红线**：不建业务表；不写业务 API；不提交真实账号、源表密码或对象存储密钥。

**易混淆**：应用展示时区与数据库存储时区分离；不要把 `Asia/Shanghai` 设为数据库存储时区。

**测试**：Q001 健康检查；Q002 配置缺失时启动失败且不打印密钥；Q003 前后端构建；Q004 Docker 依赖健康。

**验收命令**：`uv run ruff check . && uv run mypy . && uv run pytest`；`pnpm typecheck && pnpm lint && pnpm test && pnpm build`。

**DoD**：全工程可启动；规范文档、环境模板和可机器校验的追踪矩阵骨架齐全；无业务代码。

## T02 · PostgreSQL/PostGIS 全量建模

**目标**：一次建立 PRD 核心实体、索引、约束和初始状态机。

**要做什么**
- 建表覆盖组织/片区/品牌/SKU/用户授权、商家归属、合同及审批、冰柜流水、巡访任务与记录、销量、补货、排班、活动、督导整改、采购供货、费用、绩效、工资、审批、任务、审计、AI 日志、导入批次。
- 主键 UUID/ULID，对外单号唯一；所有引用历史的主数据只停用不删除。
- PostGIS `geography(Point,4326)` 存商家与打卡坐标；建立 GiST 索引。
- 金额 `BIGINT` 分；箱数 `NUMERIC(12,2)`；所有状态加数据库 CHECK；主数据与业务表含不可变 `dataset_type + dataset_id`，`is_demo` 仅作兼容字段。
- 关系约束/Service 同时校验两端数据域一致；生产环境默认 `DEMO_DATA_ENABLED=false`，演示批次导入路由不可用。
- 唯一约束至少覆盖账号、SKU、商家编号、合同号、冰柜资产号、采购单号、同一巡访任务正式记录、幂等键。

**红线**：金额禁 float；不把多值业务对象塞 JSON；审计 payload 和快照可用 JSONB；财务与资产流水不做物理删除。

**测试**：Q005 空库 migrate；Q006 downgrade/upgrade 演练；Q007 关键唯一约束；Q008 PostGIS 200 米边界；Q009 金额/箱数精度。

**人工验收**：核对所有状态、索引、外键和 `is_demo` 默认值。

**DoD**：迁移可重复执行；模型与关系图存入 `docs/data-model.md`。

## T03 · 登录、管理员建号、RBAC/ABAC

**要做什么**
- 无注册入口；系统管理员创建、停用、启用、重置账号，但不能设置或查询初始密码；系统生成一次性凭据，仅展示一次，首次使用后失效并强制设新密码。
- access/refresh token；Argon2id；会话撤销；登录失败限流；角色变更后旧 token 失效。
- `PermissionService` 同时校验能力权限、本人/片区/品牌行级范围、敏感字段权限。
- 实现业务员、经理、督导、财务、系统管理员、可选厂商 6 类权限；厂商默认待激活且受功能开关控制。
- 所有受限接口以后端依赖和 Service 二次校验，前端只负责可见性。

**红线**：系统管理员不自动获得工资发放能力；厂商不能看商家联系方式、精确坐标、成本毛利和工资。

**测试**：Q010 无注册路由；Q011 首次改密；Q012 角色 × 模块矩阵；Q013 业务员跨片区 403；Q014 厂商功能关闭不可登录；Q015 token 撤销。

**DoD**：账号全生命周期与接口级权限测试通过。

## T04 · 审计、幂等、文件与敏感字段

**要做什么**
- `AuditService` 与业务写操作同事务记录 actor、原因、前后值、request-id；失败事务不留成功审计。
- `IdempotencyService` 覆盖移动端提交、审批、AI 写工具、外部回调；同键同结果，异参冲突。
- `FileService` 只接受白名单类型/大小，计算哈希，短期签名 URL，访问时再次鉴权；预留病毒扫描状态。
- 响应 Schema 实施手机号、精确坐标、工资、成本字段裁剪；日志结构化脱敏。

**红线**：审计不能异步补写；原始定位/照片不能覆盖；不得在日志、错误、审计、导出中出现密码或完整 token。

**测试**：Q016 审计随事务回滚；Q017 幂等重放；Q018 同键异参 409；Q019 文件越权；Q020 日志敏感词扫描。

## T05 · 审批、任务与状态机内核

**要做什么**
- `ApprovalService`：不可自审、节点能力校验、退回/驳回原因、重复决定幂等。
- `TaskService`：派发、完成、交接、批量转移；同业务对象/类型/责任人未关闭时不重复创建。
- 复核任务不能在任务卡直接完成，必须打开关联单据并由单据动作关闭。
- 为合同、冰柜、补货、整改、采购、绩效、工资建立显式状态迁移服务。

**测试**：Q021 不可自审；Q022 重复审批；Q023 复核任务拒绝直接完成；Q024 交接留痕；Q025 非法状态跳转；Q026 任务幂等。

## T06 · 应用外壳、组件与演示数据底座

**要做什么**
- 角色导航、路由守卫、顶栏搜索/通知/AI 入口占位、响应式布局。
- 实现十个通用组件并测试；业务页面先放带下一步的空态。
- 建 `SeedCheckService`、`db:reset`、数据域校验器和演示数据导入骨架；此卡只准备表结构、命令和空批次，不导入依赖 SKU/账号的业务演示数据。
- 自检骨架含跨域负例：演示商家 + 生产合同、生产工资引用演示绩效、异步导出混入演示数据均必须失败。

**红线**：不实现业务功能；不在 T07 主数据完成前落演示业务数据；生产环境不得开启演示导入。

**测试**：Q027 组件渲染；Q028 角色导航；Q029 SeedCheck 空批次可运行；Q030 三类跨域负例失败；Q031 生产配置拒绝 DEMO 批次。

**里程碑 M0**：地基、安全、权限、审计、状态机与可验证数据底座完成。

# P1 · 渠道、合同与资产（T07–T10）

## T07 · 沁爽主数据 Excel 导入

**要做什么**
- 四步导入：上传、预检、确认、执行；支持用户提供的 `品牌与产品`、`账号数据`、`角色权限`、`说明`。
- 同一文件 SHA-256 或同一主键重复时只显示既有批次；34 SKU 与 15 账号不能重复创建。
- 将价格转为分；生成稳定 SKU 编码；片区映射先于账号；“全局/跨片区”转授权范围。
- 明确忽略登录密码列；管理员确认每个账号的角色、片区和启用状态；执行后单独生成一次性激活凭据。
- 角色权限表只做差异预览，不覆盖代码红线；厂商账号默认 `PENDING_ACTIVATION`。
- 导入《沁爽饮料-初始化夹具与补充演示数据.xlsx》：先落 34 SKU、15 个默认禁用/待激活账号及角色映射，再落 20 商家、8 冰柜、20 SKU 补货、调拨和排班边界场景；账号页不得含密码。
- 所有导入行固化 `dataset_type=DEMO` 与 `dataset_id=DEMO-QINSHUANG-2026Q3`；关联链数据域一致。导入完成后运行 SeedCheck 全量引用与边界校验。

**红线**：主数据批次全有或全无；不把源表明文密码写入任何目标；不自动启用厂商门户。

**测试**：Q032 34 SKU 导入；Q033 15 账号角色映射；Q034 重复文件；Q035 密码列全链路不存在；Q036 未知片区整批回滚；Q037 厂商待激活；并重跑 Q029–Q031 验证完整夹具、跨域拒绝和正式查询/异步导出零泄漏。

## T08 · 商家中心与责任归属

**要做什么**

- 责任归属用 `MerchantAssignment` 生效区间，不直接覆盖 owner；详情聚合合同、冰柜、巡访、补货、活动、整改、审计。
- 联系人和精确位置按角色脱敏；业务员只能操作本人/临时授权商家。

**测试**：Q038 重复商家提示；Q039 跨片区隔离；Q040 归属时间区间无重叠；Q041 敏感字段裁剪；Q042 URL 筛选恢复。

## T09 · 合同申请、审批与版本

**要做什么**
- 合同草稿、申请、退回、批准、生效、变更、终止申请；附件走 FileService。
- 合同固化陈列阈值、提成规则版本、生效/到期日；生效后不可覆盖，变更生成新版本。
- 只有生效合同可投柜、计新签和进入常规巡访；审批后创建相关任务。

**红线**：业务员不能自审；终止不是删除；附件文字不能指挥系统跳过审批。

**测试**：Q043 未生效禁止投柜；Q044 自审拒绝；Q045 50% 阈值固化；Q046 变更留旧版；Q047 终止前状态不变。

## T10 · 冰柜投放、撤回、验收与维修

**要做什么**
- 冰柜台账、资产流水、购置金额、投放单、撤柜任务、仓库验收、维修、报废。
- 实现 PRD 状态机；每次迁移写流水并校验当前商家唯一。
- 合同终止审批通过后创建撤柜任务；现场回收只到 `PENDING_ACCEPTANCE`；验收入库才增加可用库存。

- 性能：工作台 P95 ≤1 秒、常用列表 P95 ≤800ms、巡访提交 ≤3 秒（不含上传）；记录压测数据与查询计划。
- 观测：request-id、结构化日志、API/worker/MCP 指标、权限拒绝、导出、登录失败和 AI 降级告警。
- 灾备：每日备份、30 天恢复窗口、恢复演练；绩效/工资长期保留策略配置。
- 压测固定数据规模、并发模型、预热轮次、统计窗口、机器规格和重复次数；报告同时给 P50/P95/P99、错误率与查询计划。灾备明确 RPO≤24h、RTO≤4h，并实际恢复验证。
- 依赖、镜像与 IaC 分别用固定版本的 `pip-audit`、Trivy、Checkov 扫描；`critical/high=0` 才可上线，例外必须有到期日、负责人和书面审批。

**跨卡回归**：精确重跑 Q010–Q020、Q055–Q067、Q102–Q121、Q122–Q159；结果写回 `docs/test-traceability.csv`。

**测试**：Q166 越权矩阵；Q167 速率限制；Q168 签名 URL 过期；Q169 性能阈值；Q170 日志链路；Q171 备份恢复；Q172 故障时核心业务可用。

## T30 · 全链路 UAT、部署与上线门禁

**要做什么**
- 自动化覆盖 PRD A1–A24；逐一关联到 Q 测试或 UAT 脚本，缺一不可。
- 生成机器可检查的追踪矩阵（CSV/JSON）：每个 `Q` 映射到测试文件/测试节点、执行命令、夹具、PRD 规则与验收场景；重复、缺失或悬空引用均使 CI 失败。
- 走通：管理员建号 → Excel 导入 → 商家/合同 → 投柜 → 排班/巡访 → 补货/采购 → 撤柜 → 绩效/工资 → 报表 → MCP。

- 上线门禁：所有测试绿、无高危漏洞、迁移演练完成、备份可恢复、业务负责人签署 UAT。

# 附录 A · 首版明确不做

| 项目 | 处理方式 |
| --- | --- |
| 银行代发、真实支付、税务、发票 | 留接口和二期待办，不在首版模拟成功 |
| 电子签章、完整电子合同 | 首版只上传合同附件和版本 |
| 完整 WMS、批次、保质期、配送路线 | 首版只记录需求、采购、供货/送达状态 |
| ERP/薪酬/支付深度集成 | 使用适配器接口和 mock，不接生产系统 |
| 自动驾驶式 AI | 所有写入遵循草稿、预览、确认、审批 |
| 厂商门户默认开放 | 默认关闭，只预留开关、授权和供货确认 |
| 机器学习销量预测 | 首版只做确定性汇总与规则建议 |

AI 遇到这些需求时应留下带归属的 TODO，不得顺手实现。

# 附录 C · 卡住时怎么办

| 症状 | 处理 |
| --- | --- |
| 卡片过大 | 按“后端 Service+测试 / API+UI”拆为同一卡的两个会话，不扩大范围 |
| AI 改坏旧功能 | `git revert` 当前卡；把漏掉的约束补入红线，再重新执行 |
| 测试定义不清 | 先只写测试和数据夹具，由人确认后再实现 |
| 需求有歧义 | 回到 PRD；仍未定义则记二期待办，不自创算法 |
| 跨卡回改 | 重跑被改卡全部 Q 测试，并在本卡结果中列出 |
| 数据导入失败 | 保留批次与脱敏错误报告；不得跳过预检直接写库 |
| AI/MCP 故障 | 执行降级矩阵，核心业务继续可用 |
