盖 49%/50%、199m/201m、20 个稳定 SKU、调拨生效日前后、真实重叠时段与首尾相接、待验收冰柜当前商家为空、绩效版本生效日。

### 10.4 导入顺序与失败处理

```text
创建导入批次 → 校验文件哈希与模板版本 → 预检片区/品牌/SKU/账号
→ 管理员确认角色和授权范围 → 事务内写主数据与审计
→ 系统生成一次性激活凭据（只展示一次，不写回 Excel） → 分批导入演示业务数据
→ 运行 SeedCheckService → 输出导入报告
```

- 主数据批次采用全有或全无；任一 SKU、账号或授权校验失败时整批不落库。
- 演示业务数据允许按工作表独立批次导入，但每张表内部仍须事务一致。
- 生产环境拒绝 `dataset_type=DEMO` 批次；非生产环境也必须先导入片区/品牌/SKU/账号夹具，再导入引用它们的业务演示表。
- 已被业务引用的批次不能物理回滚，只能停用/作废并生成反向变更记录。
- 导入失败文件不得包含明文密码、完整手机号或未脱敏坐标。

## 十一、验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| A1 | 管理员创建业务员账号 | 无注册入口；管理员不能设置或查询初始密码；系统生成一次性凭据且只展示一次，首次登录后立即失效并强制设新密码。 |
| A2 | 业务员访问其他片区商家 | 列表与详情均不可见；直接调用接口返回 403/空权限结果。 |
| A3 | 合同未审批即申请投柜 | 后端拒绝；冰柜状态和库存均不改变。 |
| A4 | 合同生效后投放冰柜 | 冰柜状态为已投放，绑定商家/合同/业务员并有投放流水和照片。 |
| A5 | 有效巡访 | 定位、照片、陈列、SKU 销量/补货完整，计入周覆盖率。 |
| A6 | 定位超 200 米的巡访 | 标记异常；未经理判定前不计覆盖率和巡访绩效。 |
| A7 | 同时排活动和巡访 | 排班发布被冲突校验阻止，任何一条任务不被部分写入。 |
| A8 | 商家调拨 | 生效日之前/之后的任务与绩效归属正确，历史负责人不被改写。 |
| A9 | 商家取消并撤柜 | 回收完成后仍为待验收；验收为在库时库存才 +1，合同终止留档。 |
| A10 | 督导每周跟访 | 同一业务员两次跟访不满足“覆盖两人”；工作台发出未达标预警。 |
| A11 | 部分补货 | 已满足和未满足数量可追溯；未满足部分不被误记为完成。 |
| A12 | 绩效预计算 | 只使用生效合同、确认销量、有效巡访和对应规则版本，明细可反查。 |
| A13 | 工资已发放 | 需财务权限和二次确认；生成审计记录，之后只能通过更正单调整。 |
| A14 | 厂商用户查询数据 | 仅看到授权品牌/片区汇总；看不到商家电话、精确坐标、工资和其他品牌。 |
| A15 | AI 查询“本周我未拜访的店” | 仅返回当前业务员应访问且未有效完成的商家，附统计截至时间。 |
| A16 | AI 请求“终止某合同” | 仅生成终止申请预览，不能直接改合同/冰柜状态；审批后才创建撤柜任务。 |
| A17 | AI 重复提交补货 | 相同幂等键只创建一条补货申请。 |
| A18 | AI/模型不可用 | 巡访草稿保留原文、排班返回排序清单、经营分析返回确定性指标表；业务页面不 500。 |
| A19 | 导出报表 | 导出数据遵守用户行/字段权限，记录导出审计且链接过期。 |
| A20 | 真实数据导入 | 预检能阻止重复账号、未知片区、无效角色和重复资产号；成功导入批次可追溯。 |
| A21 | 重复 Excel 导入 | 第二次上传相同文件哈希时只显示已有批次，不重复创建 34 个 SKU 或 15 个账号。 |
| A22 | 源表含明文密码列 | 预检提示该列被忽略；数据库、日志、错误报告、审计和导出均不存在明文密码。 |
| A23 | 厂商账号导入 | 厂商门户关闭时账号为待激活且无法登录；开启功能并配置品牌/片区授权后，管理员重新发激活凭据才可登录。 |
| A24 | 演示数据隔离 | 生产默认禁用演示导入；跨数据域关系被拒绝；正式经营看板、绩效、工资、采购和同步/异步导出均显式使用 `DataScope.PRODUCTION` 且不含演示记录。 |
| A25 | 7 天未有效巡访 | 商家进入经理风险清单并在下周排班建议中处于优先位；补访并经理判定后风险关闭且留审计，重复触发不重复生成。 |
| A26 | 合同到期前 30 天 | 自动生成一次续签评估待办（重复触发不重复生成）；待办完成前合同与冰柜状态不变。 |
| A27 | 地推样品领用 | 复盘登记实际消耗与归还数量；样品成本计入活动费用，未出现在确认销量、绩效销量与库存指标中；未归还生成提醒待办。 |
| A28 | 冰柜押金收退 | 投放时登记押金收缴流水；撤柜验收后生成退押金待办，财务确认退款并留凭证；押金不出现在损益中，金额精确到分。 |

## 十二、首版边界与后续迭代

### 首版必须交付

1. 管理员创建/管理账号、RBAC + 片区/品牌行级权限、首次改密、审计。
2. 商家、合同、冰柜投放/撤柜/验收、巡访打卡、补货、周排班、商家调拨、地推、督导整改。
3. 采购建议与手工确认供货；绩效预计算、工资单状态、核心报表与导出。
4. AI 只读查询、表单草稿、执行预览、受控 MCP 工具、审计和降级。
5. 初始化导入、重复文件检测、明文密码列忽略、虚拟数据隔离、全量验收场景。
6. 风险预警清单（RK-1～RK-7）、合同到期续签评估提醒、退押金待办与地推样品领用归还台账。

### 明确不在首版范围

- 真实银行代发、支付、电子签章、税务/发票、ERP/WMS/配送系统深度对接；
- 完整仓库入库/出库/批次/保质期管理（可先保留接口）；
- 自动驾驶式 AI 操作、无人工确认的合同/工资/采购执行；
- 厂商门户默认启用（仅预留数据模型与权限开关）；
- 基于历史销量的机器学习预测与商家健康评分（首版仅规则/数据驱动建议与风险清单）。
- 语音输入、附件照片/合同 OCR、合同自动续签与电子签约（OCR 如启用须按非可信内容处理）。

### 后续迭代建议

1. 配送与库存闭环：接入进销存/仓储后，补货从需求到出库/签收全链路可追踪。
2. 电子合同与电子签章：在合规和身份认证完成后引入。
3. 预测和优化：基于可靠销量、库存、节假日、活动效果做需求预测与路线优化。
4. 厂商协同：先只读供货确认，再按合作协议扩展对账和联合营销。
