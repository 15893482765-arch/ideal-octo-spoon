# 03\.Agent状态管理

本章沿着一条租赁业务线逐步增加能力：客户说“我们电商工作室需要32台电脑”，补充地点和租期，改成24台，查询设备和库存，关闭后继续沟通，最后压缩较长的历史。

## 准备环境

`.env`内容：

```Plaintext
MCP_URL=http://127.0.0.1:8012/mcp
CONTEXT_CHAR_LIMIT=12000
```

填写自己的模型密钥。`MCP_URL`连接上一章的MCP服务，不是Java后端地址。前两节只需要模型，后三节需要启动Java业务系统和上一章的MCP服务。

每份代码开头的配置和`ask_model()`相同：通过`load_dotenv()`加载`.env`，真实调用模型并取出回复消息。

## 1\. 意图识别与信息提取：这一轮想做什么

**业务问题**：“数量改成24台”和“找16GB内存的电脑”需要不同的后续动作。

本节只让模型完成两件事：`intent`识别本轮想做什么，`changes`提取本轮明确提供的需求。

|输入|意图|提取内容|
|---|---|---|
|电商工作室要32台电脑，用于电商运营|补充需求|数量32、用途电商运营|
|数量改成24台|修改需求|数量24|
|帮我找16GB内存的电脑|查询设备|配置要求|

意图是帮助执行的线索，不需要给每一种说法写关键词规则。本例的JSON由模型生成，程序用`json.loads()`读取其中的意图和变化字段。

`extract(text)`只接收本轮输入，返回解析后的字典。

提示词只需要讲清楚三项内容：任务、意图分类、JSON输出格式。

|需求字段|含义|
|---|---|
|quantity|设备数量|
|purpose|使用用途|
|city|使用地点|
|months|租赁月数|
|budget|客户预算要求|
|configuration|设备配置要求|

**完整代码：****`01_intent_and_facts.py`**

```Python
import json
import os
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()
client = OpenAI(
    api_key=os.environ['DEEPSEEK_API_KEY'],
    base_url=os.getenv('DEEPSEEK_BASE_URL', 'https://api.deepseek.com'),
)
model = os.getenv('DEEPSEEK_MODEL', 'deepseek-flash')

def ask_model(messages, **options):
    answer = client.chat.completions.create(model=model, messages=messages, **options)
    return answer.choices[0].message


def extract(text):
    prompt = """你是电商工作室电脑租赁助手。
识别本轮意图：补充需求、修改需求、查询设备、核查库存、其他。
提取本轮明确提供的需求：quantity、purpose、city、months、budget、configuration。
只返回JSON，没提到的字段不要输出。
示例：数量改成24台
{"intent":"修改需求","changes":{"quantity":24}}
"""
    message = ask_model([
        {"role": "system", "content": prompt},
        {"role": "user", "content": text},
    ], response_format={"type": "json_object"})
    return json.loads(message.content)


while True:
    text = input('销售（输入exit退出）：').strip()
    if text == 'exit':
        break
    if not text:
        continue
    result = extract(text)
    print(json.dumps(result, ensure_ascii=False, indent=2))
```

**运行：**

```PowerShell
.venv\Scripts\python 01_intent_and_facts.py
```

**观察：**

输入“数量改成24台”，观察`intent`和`changes.quantity`。再输入“找16GB内存的办公电脑”，比较意图变化。

`response_format`要求模型返回JSON，`json.loads()`将JSON字符串转成Python字典。意图标签不是固定流程按钮，后面仍由模型结合需求和工具决定行动。

## 2\. 需求状态：只更新客户修改的字段

**业务问题**：客户改数量后，地点和租期不能丢失。

在上一节基础上增加普通字典`facts`，保存当前需求。每轮把已有需求和新输入交给模型，只提取变化，再合并。提示词在这里再补充日期规则，输出仍只包含`intent`和`changes`。

```Python
# 核心逻辑
result = extract(text, facts)
changed = update_facts(facts, result["changes"])
```

`facts.update(changes)`只覆盖本轮出现的字段，其他已有字段保持原值。`changed`记录实际变化的字段，供下一节决定是否重新查询。

起租日或租赁月数变化时，如果本轮没有提供新的结束日期，就删除旧结束日期，等待补充，避免新旧日期混用。这里的`facts.pop("end_date", None)`只删除一个失效的需求字段，不删除历史消息。

没有年份的日期默认当年；不完整的“下个月”需要澄清。`months=6`只是租期要求，查询库存需要明确起止日期，本例不自行假定每月30天。正式系统可用统一的租期计算规则生成结束日期。

**完整代码：****`02_requirement_state.py`**

```Python
import json
import os
from datetime import date
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()
client = OpenAI(
    api_key=os.environ['DEEPSEEK_API_KEY'],
    base_url=os.getenv('DEEPSEEK_BASE_URL', 'https://api.deepseek.com'),
)
model = os.getenv('DEEPSEEK_MODEL', 'deepseek-flash')

def ask_model(messages, **options):
    answer = client.chat.completions.create(model=model, messages=messages, **options)
    return answer.choices[0].message


def extract(text, facts):
    prompt = f"""你是租赁销售助手，只提取本轮明确新增或修改的信息。
    今天是{date.today().isoformat()}。日期没说年份，默认今年；不猜月份和日期。
    结合已有需求理解“改成24台”“还是原来的地点”等指代；不明确就留空。
    返回JSON：{{"intent":"意图", "changes":{{}}}}。
    intent只能是：补充需求、修改需求、查询设备、核查库存、询问政策、其他。
    changes只允许以下字段：quantity（正整数）、purpose、city、start_date、end_date、
    months（正整数）、budget（非负数）、configuration（配置要求）。
    日期格式YYYY-MM-DD。没说的字段不要输出，已知旧值不要重复输出。
    例如“数量改成24台”返回{{"intent":"修改需求","changes":{{"quantity":24}}}}。
    """
    message = ask_model([
        {"role": "system", "content": prompt},
        {"role": "user", "content": json.dumps(
            {"已有需求": facts, "本轮输入": text}, ensure_ascii=False
        )},
    ], response_format={"type": "json_object"})
    result = json.loads(message.content)
    return result

def update_facts(facts, changes):
    changed = [key for key in changes if facts.get(key) != changes[key]]
    facts.update(changes)
    if {'start_date', 'months'} & set(changed) and 'end_date' not in changes:
        facts.pop('end_date', None)
    return changed
    
facts = {}
while True:
    text = input('销售（输入exit退出）：').strip()
    if text == 'exit':
        break
    if not text:
        continue
    result = extract(text, facts)
    changed = update_facts(facts, result['changes'])
    print('意图：', result['intent'], '；变化字段：', changed)
    print('当前需求：', json.dumps(facts, ensure_ascii=False, indent=2))
    missing = [key for key in ('quantity', 'start_date', 'end_date') if not facts.get(key)]
    print('租期库存查询还缺：', missing or '信息齐全，可以结合设备编号核查')
```

```PowerShell

```

依次输入：

```Plaintext
电商工作室要32台电脑，地点郑州金水区，租6个月
```

观察数量变成24，地点和6个月要求仍保留。当前年份为2026时，11月15日解析为2026\-11\-15。日期默认值不代表客户接受了报价。

本节显示库存查询还缺什么，并未调用库存工具。客户建档和正式报价留在业务系统处理；查询设备目录不需要客户编号。

## 3\. 接入MCP：让需求驱动真实查询

**业务问题**：需求收集之后，要查真实目录和库存，而不是继续泛泛聊天。

先启动上一章的MCP服务。本节发现`search_devices`和`check_availability`两个工具，把描述和Schema传给模型。模型决定是否调用、调用哪个工具和参数是什么，程序执行并把结果回传。

```Plaintext
提取需求 → 更新facts → 模型选择工具 → MCP执行 → 结果回传 → 模型继续判断
```

`run_turn()`是核心执行循环，最多调用模型5次。`main()`只负责连接MCP和接受输入。没有按意图写死一条workflow。

信息提取会结合最近对话理解“刚才那款”，将已选型号的真实编号保存为`model_id`。需求发生变化时保留对话历史，同时把最新需求和本轮变化字段传给模型。例如32台改24台，旧的32台库存结果保留在历史中，但不能作为当前24台需求的核验结论，必须重新查询。

这两个工具都是查询工具。本例不会创建客户、报价和订单。库存查询需要真实设备编号和日期，模型不能拿型号名称假冒编号。

**完整代码：****`03_agent_with_mcp.py`**

```Python
import asyncio
from mcp import ClientSession
from mcp.client.streamable_http import streamable_http_client

import json
import os
from datetime import date
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()
client = OpenAI(
    api_key=os.environ['DEEPSEEK_API_KEY'],
    base_url=os.getenv('DEEPSEEK_BASE_URL', 'https://api.deepseek.com'),
)
model = os.getenv('DEEPSEEK_MODEL', 'deepseek-flash')

def ask_model(messages, **options):
    answer = client.chat.completions.create(model=model, messages=messages, **options)
    return answer.choices[0].message


def extract(text, facts, history):
    prompt = f"""你是租赁销售助手，只提取本轮明确新增或修改的信息。
    今天是{date.today().isoformat()}。日期没说年份，默认今年；不猜月份和日期。
    结合已有需求理解“改成24台”“还是原来的地点”等指代；不明确就留空。
    返回JSON：{{"intent":"意图", "changes":{{}}}}。
    intent只能是：补充需求、修改需求、查询设备、核查库存、询问政策、其他。
    changes只允许以下字段：quantity（正整数）、purpose、city、start_date、end_date、
    months（正整数）、budget（非负数）、configuration（配置要求）、model_id（选定型号编号）。
    model_id只能来自客户明确提供的编号或此前目录查询结果；指代不明确时不要填写编号。
    日期格式YYYY-MM-DD。没说的字段不要输出，已知旧值不要重复输出。
    例如“数量改成24台”返回{{"intent":"修改需求","changes":{{"quantity":24}}}}。
    """
    message = ask_model([
        {"role": "system", "content": prompt},
        {"role": "user", "content": json.dumps(
            {"已有需求": facts, "最近对话": history, "本轮输入": text}, ensure_ascii=False
        )},
    ], response_format={"type": "json_object"})
    result = json.loads(message.content)
    return result

def update_facts(facts, changes):
    changed = [key for key in changes if facts.get(key) != changes[key]]
    facts.update(changes)
    if {'start_date', 'months'} & set(changed) and 'end_date' not in changes:
        facts.pop('end_date', None)
    return changed

async def run_turn(session, tools, state, text):
    result = extract(text, state['facts'], state['messages'])
    changed = update_facts(state['facts'], result['changes'])
    if changed:
        print('需求更新：', changed, '；相关库存需要重新核验')
    prompt = f"""你是租赁销售助手，用简短中文回答。
    当前需求：{json.dumps(state['facts'], ensure_ascii=False)}
    本轮意图：{result['intent']}；变化字段：{changed}
    设备选型不需要客户编号或日期，能查询时直接查询。
    租期库存必须有设备编号、数量、明确的起止日期；缺少时只补问缺项。
    只有月份租期时不能自行假定月末或天数。本例结束日期不含当天。
    不得承诺预留、报价保存或下单，当前只开放查询工具。
    以当前需求为准。历史库存若与当前型号、数量或日期不一致，必须重新查询。
    旧查询消息被压缩后，需要时重新查询。"""
    state['messages'].append({'role': 'user', 'content': text})
    for _ in range(5):
        reply = ask_model([{'role': 'system', 'content': prompt}] + state['messages'], tools=tools)
        state['messages'].append(reply.model_dump(exclude_none=True))
        if not reply.tool_calls:
            print('AI：', reply.content)
            return
        for call in reply.tool_calls:
            name = call.function.name
            arguments = json.loads(call.function.arguments)
            print('调用：', name, arguments)
            output = await session.call_tool(name, arguments)
            body = output.model_dump(mode='json', exclude_none=True)
            content = json.dumps(body, ensure_ascii=False)
            print('结果：', content)
            state['messages'].append({'role': 'tool', 'tool_call_id': call.id, 'content': content})
    state['messages'].append({'role': 'assistant', 'content': '本轮达到执行上限，请缩小查询范围后继续。'})
    print('AI：本轮达到执行上限，请缩小查询范围后继续。')

async def main():
    state = {'facts': {}, 'messages': []}
    url = os.getenv('MCP_URL', 'http://127.0.0.1:8012/mcp')
    async with streamable_http_client(url) as (read, write, _):
        async with ClientSession(read, write) as session:
            await session.initialize()
            discovered = await session.list_tools()
            tools = [{"type": "function", "function": {
                "name": tool.name, "description": tool.description or "",
                "parameters": tool.inputSchema,
            }} for tool in discovered.tools]
            print('可用工具：', [tool['function']['name'] for tool in tools])
            while True:
                text = input('销售（输入exit退出）：').strip()
                if text == 'exit':
                    break
                if not text:
                    continue
                await run_turn(session, tools, state, text)

if __name__ == '__main__':
    asyncio.run(main())
```

**运行：**

```PowerShell
.venv\Scripts\python 03_agent_with_mcp.py
```

**观察：**

先输入“帮我查询16GB内存的办公电脑”。应看到“调用”和真实MCP“结果”，之后才是AI回复。

再输入“选刚才目录中的某个实际型号，24台，2026年11月15日起租，2027年5月15日归还，核查库存”。将“某个实际型号”换成刚才查到的名称或编号。观察是否调用`check_availability`。

缺信息时应只补问缺项；工具报错时，模型应说明失败，不能编造成功库存。查询结果只代表查询时点的可用情况。

## 4\. 会话保存：关闭程序之后还能继续

**业务问题**：销售关闭程序后，第二次打开还需要重新填写吗？

在上一节基础上增加两个函数：`load_session()`读取，`save_session()`保存。文件只保存两项内容：当前需求`facts`和完整消息`messages`。工具调用和返回结果已经保存在消息中。

```Python
state = load_session()          # 启动时恢复
await run_turn(...)            # 执行本轮
save_session(state)            # 成功后保存
```

`write_text()`将会话写入`session.json`，`read_text()`读回内容，再由`json.loads()`恢复成字典。

此处演示一个会话，本地JSON容易看清原理；正式系统需要按员工和会话编号**隔离**，并保存到数据库。

> 员工1  \-\-\> 会话1  
> 
> \-\-\> 会话2
> 
> 员工2  \-\-\> 会话1
> 
>

## 5\. 上下文压缩：保留业务事实，缩短聊天历史

**业务问题**：聊得越来越长，全部历史都发送给模型会增加开销，也可能超过上下文容量。

在上一节基础上增加`compact_context()`。每轮工具执行结束后检查字符数，超过阈值时保留：

- 当前需求`facts`，作为需求摘要。

- 最近两轮完整消息，包含其中的工具调用和结果。

本例直接保留结构化需求和最近两轮消息，不额外调用模型生成摘要。当前需求会放进下一轮system消息，最近消息继续通过`messages`传给模型。旧查询结果被删除后，需要时重新查询。

裁剪从`user`消息边界开始，避免保留工具结果却丢了对应的工具调用。最近两轮仍然很大时，本例保留它们并提示减少工具返回数据，不硬截断协议消息。

`CONTEXT_CHAR_LIMIT`是字符阈值，便于课堂观察，并非精确token限制。实际工程应结合模型容量、输出预算及token统计设置策略。压缩发生在完整轮次之间。

**完整代码：****`05_context_compaction.py`**

```Python
import asyncio
from mcp import ClientSession
from mcp.client.streamable_http import streamable_http_client

import json
import os
from datetime import date
from pathlib import Path
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()
client = OpenAI(
    api_key=os.environ['DEEPSEEK_API_KEY'],
    base_url=os.getenv('DEEPSEEK_BASE_URL', 'https://api.deepseek.com'),
)
model = os.getenv('DEEPSEEK_MODEL', 'deepseek-flash')

def ask_model(messages, **options):
    answer = client.chat.completions.create(model=model, messages=messages, **options)
    return answer.choices[0].message


def extract(text, facts, history):
    prompt = f"""你是租赁销售助手，只提取本轮明确新增或修改的信息。
    今天是{date.today().isoformat()}。日期没说年份，默认今年；不猜月份和日期。
    结合已有需求理解“改成24台”“还是原来的地点”等指代；不明确就留空。
    返回JSON：{{"intent":"意图", "changes":{{}}}}。
    intent只能是：补充需求、修改需求、查询设备、核查库存、询问政策、其他。
    changes只允许以下字段：quantity（正整数）、purpose、city、start_date、end_date、
    months（正整数）、budget（非负数）、configuration（配置要求）、model_id（选定型号编号）。
    model_id只能来自客户明确提供的编号或此前目录查询结果；指代不明确时不要填写编号。
    日期格式YYYY-MM-DD。没说的字段不要输出，已知旧值不要重复输出。
    例如“数量改成24台”返回{{"intent":"修改需求","changes":{{"quantity":24}}}}。
    """
    message = ask_model([
        {"role": "system", "content": prompt},
        {"role": "user", "content": json.dumps(
            {"已有需求": facts, "最近对话": history, "本轮输入": text}, ensure_ascii=False
        )},
    ], response_format={"type": "json_object"})
    result = json.loads(message.content)
    return result

def update_facts(facts, changes):
    changed = [key for key in changes if facts.get(key) != changes[key]]
    facts.update(changes)
    if {'start_date', 'months'} & set(changed) and 'end_date' not in changes:
        facts.pop('end_date', None)
    return changed
SESSION_FILE = Path(__file__).with_name('session.json')

def load_session():
    if SESSION_FILE.exists():
        saved = json.loads(SESSION_FILE.read_text(encoding='utf-8'))
        return {'facts': saved['facts'], 'messages': saved['messages']}
    return {'facts': {}, 'messages': []}

def save_session(state):
    SESSION_FILE.write_text(json.dumps(state, ensure_ascii=False, indent=2), encoding='utf-8')

def compact_context(state):
    messages = state['messages']
    characters = len(json.dumps(state, ensure_ascii=False))
    threshold = int(os.getenv('CONTEXT_CHAR_LIMIT', '12000'))
    print(f'上下文字符数：{characters}；压缩阈值：{threshold}')
    if characters <= threshold:
        return
    starts = [i for i, message in enumerate(messages) if message['role'] == 'user']
    if len(starts) <= 2:
        print('不足三轮，保留完整工具链；可减少单次工具返回的数据量')
        return
    state['messages'] = messages[starts[-2]:]
    print('已压缩：保留当前需求和最近两轮完整消息')

async def run_turn(session, tools, state, text):
    result = extract(text, state['facts'], state['messages'])
    changed = update_facts(state['facts'], result['changes'])
    if changed:
        print('需求更新：', changed, '；相关库存需要重新核验')
    prompt = f"""你是租赁销售助手，用简短中文回答。
    当前需求：{json.dumps(state['facts'], ensure_ascii=False)}
    本轮意图：{result['intent']}；变化字段：{changed}
    设备选型不需要客户编号或日期，能查询时直接查询。
    租期库存必须有设备编号、数量、明确的起止日期；缺少时只补问缺项。
    只有月份租期时不能自行假定月末或天数。本例结束日期不含当天。
    不得承诺预留、报价保存或下单，当前只开放查询工具。
    以当前需求为准。历史库存若与当前型号、数量或日期不一致，必须重新查询。
    旧查询消息被压缩后，需要时重新查询。"""
    state['messages'].append({'role': 'user', 'content': text})
    for _ in range(5):
        reply = ask_model([{'role': 'system', 'content': prompt}] + state['messages'], tools=tools)
        state['messages'].append(reply.model_dump(exclude_none=True))
        if not reply.tool_calls:
            print('AI：', reply.content)
            return
        for call in reply.tool_calls:
            name = call.function.name
            arguments = json.loads(call.function.arguments)
            print('调用：', name, arguments)
            output = await session.call_tool(name, arguments)
            body = output.model_dump(mode='json', exclude_none=True)
            content = json.dumps(body, ensure_ascii=False)
            print('结果：', content)
            state['messages'].append({'role': 'tool', 'tool_call_id': call.id, 'content': content})
    state['messages'].append({'role': 'assistant', 'content': '本轮达到执行上限，请缩小查询范围后继续。'})
    print('AI：本轮达到执行上限，请缩小查询范围后继续。')


async def main():
    state = load_session()
    print('已恢复需求：', state['facts'])
    url = os.getenv('MCP_URL', 'http://127.0.0.1:8012/mcp')
    async with streamable_http_client(url) as (read, write, _):
        async with ClientSession(read, write) as session:
            await session.initialize()
            discovered = await session.list_tools()
            tools = [{"type": "function", "function": {
                "name": tool.name, "description": tool.description or "",
                "parameters": tool.inputSchema,
            }} for tool in discovered.tools
                if tool.name in {"search_devices", "check_availability"}]
            print('可用工具：', [tool['function']['name'] for tool in tools])
            while True:
                text = input('销售（输入exit退出）：').strip()
                if text == 'exit':
                    break
                if not text:
                    continue
                await run_turn(session, tools, state, text)
                compact_context(state)
                save_session(state)
if __name__ == '__main__':
    asyncio.run(main())
```


将`.env`中的`CONTEXT_CHAR_LIMIT`临时改为`2000`。连续输入三轮以上，不修改需求，例如查询目录、追问已查设备的配置、询问两款的差异。

观察“已压缩”提示，再问“现在数量和起租日期是什么”。模型应仍能依据`facts`回答。随后改成20台，再核查库存，观察对话历史仍保留，但按新数量重新查询库存。

若没有触发，可增加几轮追问；如果不断修改需求，旧消息会被清理，可能达不到阈值。演示后恢复12000。

## 核心逻辑回顾

```Plaintext
新输入 → 提取意图和变化 → 更新需求
      → 模型结合需求选择工具 → 执行 → 结果回传 → 回复
      → 必要时压缩 → 保存会话 → 下一轮
```

`facts`保存当前需求，`messages`保存对话、工具调用和返回结果。模型负责理解和选择行动，程序负责调用工具、回传结果、保存和压缩。

2. 没有起租日期时，为什么仍可以查询设备目录？

3. 为什么压缩时要保留完整的工具调用与结果，而不是随便删掉前几条消息？
