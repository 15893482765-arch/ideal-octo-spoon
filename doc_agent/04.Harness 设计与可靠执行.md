# 04\.Harness 设计与可靠执行

## 学习目标

本章学习如何把模型、工具和状态组织成可靠的 Agent Harness。从最小循环开始，逐步加入工具白名单、参数校验、权限控制、执行上限、结束状态、幂等和未知结果处理。

## 1\. 裸 Agent 只会循环

本章先创建 `model.py`，再通过阶段文件逐步加入工具和 Harness 能力，最后整合到 `harness.py` 和 `main.py`。

### 知识点

前三章的 Agent 可以表示为：

```Plaintext
用户 → 模型 → 工具 → 模型 → 回复
```

一次真实工具调用通常包含两次模型请求：第一次返回工具名称和参数；程序执行工具后，把工具结果放回消息列表；第二次请求让模型根据真实结果继续判断或生成回复。

### 代码示例 1：真实模型调用

文件：`model.py`。

```Python
import os
from openai import OpenAI
from dotenv import load_dotenv

load_dotenv()

class ModelError(Exception):
    pass

class DeepSeekModel:
    def __init__(self):
        self.client = OpenAI(
            api_key=os.environ["DEEPSEEK_API_KEY"],
            base_url=os.getenv("DEEPSEEK_BASE_URL", "https://api.deepseek.com"),
        )

    def reply(self, messages, tools=None):
        options = {
            "model": os.getenv("DEEPSEEK_MODEL", "deepseek-flash"),
            "messages": messages,
        }
        if tools:
            options.update(tools=tools, tool_choice="auto")
        response = self.client.chat.completions.create(**options)
        choice = response.choices[0]
        if choice.finish_reason not in ("stop", "tool_calls"):
            raise ModelError("模型输出没有正常结束")
        return choice.message.model_dump(exclude_none=True)

if __name__ == "__main__":
    model = DeepSeekModel()
    message = model.reply([{"role": "user", "content": "用一句话解释 Agent Harness"}])
    print(message["content"])
```

运行：

```PowerShell
python model.py
```

### 代码说明

这里有三个角色：

- `DeepSeekModel.reply()`：向真实 DeepSeek 模型发送消息和工具定义。

- `messages`：保存用户消息、模型工具请求和工具结果。

- `tools`：告诉模型有哪些工具可以申请。

模型只提出工具请求，程序仍然需要在 Harness 中校验和执行。下一节把工具白名单接到这条真实调用链上。

`finish_reason` 需要检查。`tool_calls` 表示模型请求程序行动，`stop` 表示模型已经完成文字回复，其他结束原因不能直接交给业务执行。

## 3\. 参数校验和权限

模型可以选择调用哪个工具，但是否允许执行，由 Harness 的程序规则决定。这就是 Agent = Model \+ Harness 在权限控制中的分工。

沿用参考代码的 reader、editor 两种角色：reader 只能查询任务，editor 可以查询和创建任务。下面用一个独立文件讲清楚执行边界

保存为 permission\_demo\.py。为了直接验证权限规则，本例不调用模型，而是手动提供工具名和参数；任务实际写入内存 SQLite，退出后数据清除。

```Python
import sqlite3

db = sqlite3.connect(':memory:')
db.execute('CREATE TABLE tasks (id INTEGER PRIMARY KEY, title TEXT NOT NULL)')

ROLE_TOOLS = {
    'reader': {'list_tasks'},
    'editor': {'list_tasks', 'create_task'},
}


def list_tasks():
    return db.execute('SELECT id, title FROM tasks').fetchall()


def create_task(title):
    with db:
        cursor = db.execute('INSERT INTO tasks (title) VALUES (?)', (title,))
    return {'task_id': cursor.lastrowid, 'title': title}


TOOLS = {'list_tasks': list_tasks, 'create_task': create_task}


def run_tool(name, args, *, role):
    if name not in TOOLS:
        return {'ok': False, 'error': 'TOOL_NOT_ALLOWED'}
    if name not in ROLE_TOOLS.get(role, set()):
        return {'ok': False, 'error': 'PERMISSION_DENIED'}

    fields = {'title'} if name == 'create_task' else set()
    if not isinstance(args, dict) or set(args) != fields:
        return {'ok': False, 'error': 'INVALID_ARGUMENTS'}
    if name == 'create_task':
        title = args['title']
        if not isinstance(title, str) or not 1 <= len(title.strip()) <= 80:
            return {'ok': False, 'error': 'INVALID_ARGUMENTS'}
        args = {'title': title.strip()}

    return {'ok': True, 'data': TOOLS[name](**args)}


if __name__ == '__main__':
    print(run_tool('list_tasks', {}, role='reader'))
    print(run_tool('create_task', {'title': '核对设备需求'}, role='reader'))
    print(run_tool('create_task', {'title': '核对设备需求'}, role='editor'))
    print(run_tool('create_task', {'title': '核对设备需求', 'role': 'editor'}, role='reader'))
    print(run_tool('list_tasks', {}, role='reader'))
    db.close()
```

运行：python permission\_demo\.py。

五次调用的结果依次为：查询成功且为空；reader 创建被拒绝；editor 创建成功；reader 即使在参数中写入 role=editor 仍被拒绝；reader 查询到刚刚创建的一条任务。

按三个步骤看 run\_tool\(\)：先确认工具已注册，再用执行上下文中的 role 检查角色权限，最后校验参数并执行工具。ROLE\_TOOLS 控制“能做什么”，TOOLS 保存“怎么执行”。未知角色默认没有权限。

run\_tool\(\) 的 role 是程序单独传入的执行上下文，不从 args 读取。模型在 args 中增加 role 不会提升权限；即使有创建权限，多传字段也会被参数校验拒绝。真实 Agent 中，工具名称和 args 来自模型的 tool\_calls，role 来自已经验证的登录身份。

本例直接指定角色，用于对照执行结果，没有实现登录认证。接入业务系统后，后端必须根据验证后的身份再次授权，不能直接信任调用方声明的角色。Prompt 和工具 Schema 都不能代替这一步。

## 4\. 状态和结束状态

### 知识点

Agent 的一次运行不只是“模型回复了一段文字”。在执行过程中，Harness 需要知道当前任务处于什么阶段、是否已经拿到外部系统的结果、是否还可以继续调用工具，以及发生错误后能否恢复。

例如，

用户说“登记一个任务”，模型可能先调用 `create_task`。如果工具返回任务编号，任务才拥有完成证据；

如果工具超时，程序不能把它直接标记为失败，因为服务端可能已经写入；

如果用户没有提供标题，则任务不应该调用写入工具，而应该进入需要补充信息的状态。

因此，状态至少要同时包含两部分：

```Plaintext
业务状态：当前是否已经创建任务、任务编号是什么
运行状态：本轮是完成、补充信息、失败、超限还是结果未知
```

不能只返回一句文字。Harness 要返回机器可判断的状态：

自然语言回复给用户阅读，状态字段给程序判断。

保存会话、允许恢复、转人工和停止重试都依赖状态字段，不能只搜索回复里是否出现“完成”。

```Python
COMPLETED = "completed"
NEED_INPUT = "need_input"
FAILED = "failed"
LIMIT_REACHED = "limit_reached"
UNKNOWN_OUTCOME = "unknown_outcome"
```

这五种状态的含义不同：

|状态|含义|是否可以直接重试|
|---|---|---|
|`completed`|已经拿到足够的成功证据|不需要|
|`need_input`|用户信息不足，任务尚未执行|补充信息后重新运行|
|`failed`|已明确失败，且没有待核对写入|根据错误修复后重试|
|`limit_reached`|达到模型或工具调用预算|需要缩小任务或人工处理|
|`unknown_outcome`|写入结果无法确认|只能先查询凭据，不能直接重写|

### 状态结构

文件：`state.py`。下面是状态模块。它不调用模型，只负责保存和判断状态；真实模型产生的工具结果由 `harness.py` 交给这些函数处理。

```Python
import json
from dataclasses import dataclass, field


COMPLETED = "completed"
NEED_INPUT = "need_input"
FAILED = "failed"
LIMIT_REACHED = "limit_reached"
UNKNOWN_OUTCOME = "unknown_outcome"


@dataclass
class AgentState:
    request_id: str
    status: str = "running"
    task_id: int | None = None
    steps: int = 0
    tool_calls: int = 0
    last_error: str | None = None
    messages: list[dict] = field(default_factory=list)

    def as_dict(self):
        return {
            "request_id": self.request_id,
            "status": self.status,
            "task_id": self.task_id,
            "steps": self.steps,
            "tool_calls": self.tool_calls,
            "last_error": self.last_error,
            "messages": self.messages,
        }


def finish(state, status, message):
    allowed = {COMPLETED, NEED_INPUT, FAILED, LIMIT_REACHED, UNKNOWN_OUTCOME}
    if status not in allowed:
        raise ValueError(f"unknown status: {status}")

    # completed 必须有工具成功返回的任务编号。
    if status == COMPLETED and state.task_id is None:
        state.status = FAILED
        state.last_error = "NO_SUCCESS_EVIDENCE"
        return {"status": FAILED, "message": "没有任务凭据，不能宣布完成"}

    state.status = status
    return {"status": status, "message": message}


def apply_tool_result(state, tool_name, result):
    state.tool_calls += 1
    state.messages.append({"tool": tool_name, "result": result})

    if result.get("ok") is True and tool_name == "create_task":
        state.task_id = result["data"]["task_id"]
        return

    if result.get("error") == "UNKNOWN_OUTCOME":
        state.status = UNKNOWN_OUTCOME
        state.last_error = "UNKNOWN_OUTCOME"
    elif result.get("ok") is False:
        state.last_error = result.get("error", "TOOL_FAILED")


if __name__ == "__main__":
    state = AgentState(request_id="req-state-1")
    apply_tool_result(state, "create_task", {"ok": True, "data": {"task_id": 7}})
    print(json.dumps(finish(state, COMPLETED, "任务已登记"), ensure_ascii=False))
    print(json.dumps(state.as_dict(), ensure_ascii=False, indent=2))
```

运行：

```PowerShell
python state.py
```

这个文件的作用是把“模型说完成”和“程序有完成证据”分开。`task_id` 只能来自工具返回，不能来自模型的自然语言。

### 结束状态的判断

模型可以建议结束，Harness 决定是否允许结束。真实运行时，模型返回 `finish` 工具调用后，`harness.py` 应先检查 `AgentState.task_id`，再决定是否接受 `completed`。

如果没有任务编号，程序返回 `failed` 和 `NO_SUCCESS_EVIDENCE`；如果工具返回 `UNKNOWN_OUTCOME`，程序返回 `unknown_outcome`，并保留 `request_id`，供后续恢复。

## 5\. 调用上限

### 知识点

模型调用不是一次函数调用，而是一个可能持续多轮的循环。模型可能重复查询、反复修正参数，或者在工具失败后不断尝试。因此 Harness 至少要限制三种预算：

|预算|统计对象|解决的问题|
|---|---|---|
|`max_steps`|模型请求轮次|防止模型在上下文中无限循环|
|`max_tool_calls`|实际执行的工具次数|控制外部服务压力和成本|
|`max_same_tool_calls`|同一个工具的连续次数|防止重复调用同一个工具|

计数要在执行前检查，在真正调用工具前增加。这样一旦预算耗尽，就不会多执行一次工具。`finish` 也需要占用一个模型轮次，但它不是业务工具，不应被算入外部工具调用次数。

达到上限时，Harness 必须返回 `limit_reached`。已经成功执行的查询结果可以保留在状态中，但因为任务没有走到合法结束，不能返回 `completed`。

### 完整代码

文件：`budget.py`。这是预算控制模块；真实 Harness 的模型循环使用其中的 `Budget` 类。

```Python
from dataclasses import dataclass, field


@dataclass
class Budget:
    max_steps: int = 5
    max_tool_calls: int = 8
    max_same_tool_calls: int = 3
    steps: int = 0
    tool_calls: int = 0
    tool_counts: dict[str, int] = field(default_factory=dict)

    def before_model(self):
        if self.steps >= self.max_steps:
            return False, "MODEL_STEP_LIMIT"
        self.steps += 1
        return True, None

    def before_tool(self, name):
        if name == "finish":
            return True, None
        if self.tool_calls >= self.max_tool_calls:
            return False, "TOOL_CALL_LIMIT"
        used = self.tool_counts.get(name, 0)
        if used >= self.max_same_tool_calls:
            return False, "SAME_TOOL_LIMIT"
        self.tool_calls += 1
        self.tool_counts[name] = used + 1
        return True, None

    def as_dict(self):
        return {
            "steps": self.steps,
            "tool_calls": self.tool_calls,
            "tool_counts": self.tool_counts,
            "limits": {
                "max_steps": self.max_steps,
                "max_tool_calls": self.max_tool_calls,
                "max_same_tool_calls": self.max_same_tool_calls,
            },
        }


def run_actions(actions):
    budget = Budget(max_steps=4, max_tool_calls=3, max_same_tool_calls=2)
    for action in actions:
        ok, error = budget.before_model()
        if not ok:
            return {"status": "limit_reached", "error": error,
                    "budget": budget.as_dict()}

        name = action["tool"]
        ok, error = budget.before_tool(name)
        if not ok:
            return {"status": "limit_reached", "error": error,
                    "budget": budget.as_dict()}

        if name == "finish":
            return {"status": action["status"], "budget": budget.as_dict()}

    return {"status": "limit_reached", "error": "NO_FINISH",
            "budget": budget.as_dict()}


if __name__ == "__main__":
    print(run_actions([
        {"tool": "list_tasks"},
        {"tool": "list_tasks"},
        {"tool": "finish", "status": "completed"},
    ]))
    print(run_actions([
        {"tool": "list_tasks"},
        {"tool": "list_tasks"},
        {"tool": "list_tasks"},
    ]))
```

运行：

```PowerShell
python budget.py
```

第一个示例在预算内调用 `finish`；第二个示例第三次重复调用 `list_tasks`，返回 `SAME_TOOL_LIMIT`。在最终 `harness.py` 中，模型每次请求前调用 `before_model()`，每个工具真正执行前调用 `before_tool(name)`，不能只在循环结束后才统计。

### 预算耗尽时的状态处理

`limit_reached` 不是 `failed` 的同义词。它表示 Harness 主动停止了运行，可能已经得到部分事实，但没有得到完整结论。恢复时应保留原 `request_id` 和消息记录；如果最后一个动作是写入，还要根据幂等凭据判断是否存在 `unknown_outcome`，不能简单地重新提交。

## 6\. 重试、幂等和未知结果

### 查询与写入的区别

查询和写入的可靠性规则不同。查询没有副作用，失败后再查询通常不会产生重复业务结果；写入会改变外部状态，客户端超时并不能说明服务端没有执行。

例如：

```Plaintext
客户端发送 create_task
服务端写入任务 产生任务：7
服务端响应在网络中丢失
客户端收到 timeout
```

如果此时直接重新发送 `create_task`，可能得到任务 8。Harness 必须把“重试请求”和“核对原请求结果”分开。

### 幂等键

幂等键是一次业务操作的稳定编号，通常由 `request_id` 和操作名称组成：

```Python
operation_key = request_id + "-create"
```

服务端保存 `operation_key -> result`。相同操作键和相同参数再次到达时，服务端返回原结果；相同操作键但参数不同，则返回冲突。这样客户端可以安全地重发同一个请求，而不会创建第二条业务记录。

### 完整代码

文件：`reliability.py`。下面代码展示只读重试、幂等写入、未知结果和恢复；真实模型产生的工具参数会在 `harness.py` 中调用这些方法。

```Python
class TemporaryReadError(Exception):
    pass


class TaskService:
    def __init__(self):
        self.tasks = {}
        self.operations = {}
        self.read_failures = 0

    def list_tasks(self):
        if self.read_failures > 0:
            self.read_failures -= 1
            raise TemporaryReadError("查询服务暂时不可用")
        return {"ok": True, "data": {"tasks": list(self.tasks.values())}}

    def create_task(self, operation_key, title):
        old = self.operations.get(operation_key)
        if old is not None:
            if old["title"] != title:
                return {"ok": False, "error": "IDEMPOTENCY_CONFLICT"}
            return {"ok": True, "data": old, "replayed": True}

        task = {"task_id": len(self.tasks) + 1, "title": title}
        self.tasks[task["task_id"]] = task
        self.operations[operation_key] = task
        return {"ok": True, "data": task, "replayed": False}

    def find_operation(self, operation_key):
        return self.operations.get(operation_key)


def read_with_retry(service, max_retries=2):
    for attempt in range(max_retries + 1):
        try:
            return service.list_tasks()
        except TemporaryReadError as error:
            if attempt == max_retries:
                return {"ok": False, "error": "READ_FAILED", "message": str(error)}


def write_once(service, operation_key, title):
    result = service.create_task(operation_key, title)
    if result["ok"]:
        return result
    return {"ok": False, "status": "failed", "error": result["error"]}


def recover(service, operation_key):
    # 恢复只能查询凭据，不能再次调用 create_task。
    result = service.find_operation(operation_key)
    if result is None:
        return {"status": "unknown_outcome", "operation_key": operation_key}
    return {"status": "completed", "data": result, "recovered": True}


if __name__ == "__main__":
    service = TaskService()
    service.read_failures = 2
    print("只读重试：", read_with_retry(service))

    key = "req-1-create"
    print("第一次写入：", write_once(service, key, "准备第四章"))
    print("相同操作重发：", write_once(service, key, "准备第四章"))
    print("参数冲突：", write_once(service, key, "另一个标题"))

    unknown_key = "req-2-create"
    print("未知结果恢复：", recover(service, unknown_key))
    print("已知结果恢复：", recover(service, key))
```

运行：

```PowerShell
python reliability.py
```

### 状态转换

写入请求发出前，Harness 保存 `pending`；收到任务凭据后保存 `confirmed`；收到明确的参数或权限错误后保存 `rejected`；网络超时且暂时无法查询凭据时保存 `unknown`。

```Plaintext
pending → confirmed       已拿到任务编号
pending → rejected        服务明确拒绝
pending → unknown         响应丢失或凭据服务不可用
unknown → confirmed       恢复查询查到任务编号
unknown → unknown         恢复查询仍然无法确认
```

文件：`harness.py`。只有查到任务编号，状态才可以从 `unknown_outcome` 变成 `completed`；恢复过程不能重新提交写入。
